# Glampro — Salon Pro platform

Rebuild of the Glampro salon management system as a Docker-first monorepo:
point of sale, appointments, customers, staff, inventory and reporting, built to
the **Salon Pro** redesign handoff.

| Piece              | Stack                                                          |
| ------------------ | -------------------------------------------------------------- |
| `apps/web`         | React 19 · TypeScript · Vite 8 · Tailwind 4 · TanStack Query 5 |
| `apps/api`         | Express 5 · TypeScript · Prisma 7 · Zod                        |
| `packages/shared`  | Zod schemas, API contracts and domain constants shared by both |
| Database           | PostgreSQL 17                                                  |
| Everything runs in | Docker Compose                                                 |

Architecture, conventions and design decisions: [`docs/architecture.md`](docs/architecture.md).
Containers, deployments and secret handling: [`README.Docker.md`](README.Docker.md).

## Quick start

Requirements: **Docker Engine with Compose v2**. Node.js 24 is only needed for
editor tooling and host-side scripts; nothing else has to be installed.

```bash
git clone <repo> glampro_new && cd glampro_new

cp .env.docker.example .env.docker     # then edit the two secrets
docker compose --env-file .env.docker up --build -d
```

| URL                                | What                                                   |
| ---------------------------------- | ------------------------------------------------------ |
| <http://localhost:5173>            | Salon Pro web app (Vite, hot reload)                   |
| <http://localhost:5173/api/health> | API readiness through the dev proxy                    |
| <http://localhost:9000/health>     | API liveness                                           |
| `localhost:5433`                   | PostgreSQL (`glampro` + the password in `.env.docker`) |

On first boot the API container applies migrations, generates the Prisma client
and seeds development users:

| Role        | Email                  | Password       |
| ----------- | ---------------------- | -------------- |
| Super admin | `admin@glampro.test`   | `ChangeMe123!` |
| Manager     | `manager@glampro.test` | `Manager123!`  |
| Staff       | `stylist@glampro.test` | `Staff123!`    |
| Cashier     | `cashier@glampro.test` | `Cashier123!`  |

Seed credentials are development-only. `SEED_MODE=production` creates exactly one
administrator from the `ADMIN_*` variables and nothing else.

Stop the stack with `make down`; wipe it including the database volume with
`make nuke`.

## Everyday commands

`make help` lists every target. The ones used most:

```bash
make up            # start (build if needed)
make logs          # follow api + web logs
make migrate-dev name=add_customers   # create + apply a migration
make seed          # (re)seed development data
make reset-db      # drop, migrate, seed — destructive
make test          # every test suite
make verify        # format check + lint + typecheck + tests
make smoke         # curl the running stack end to end
make rebuild       # rebuild images and refresh the node_modules volumes
```

Working outside Docker is supported too:

```bash
npm install                                 # npm workspaces: both apps + shared
docker compose --env-file .env.docker up -d database
cp apps/api/.env.example apps/api/.env      # point DATABASE_URL at localhost:5433
npm run dev                                 # shared watcher + API + web together
```

## Conventions at a glance

- **TypeScript everywhere**, strict, with `erasableSyntaxOnly` — no enums, no
  runtime namespaces, no parameter properties.
- **Server state lives in TanStack Query**; query keys come from
  `apps/web/src/constants/queryKeys.ts` so invalidation always matches.
- **All HTTP goes through `apps/web/src/lib/api.ts`**; components never call
  axios directly.
- **Shared contracts live in `packages/shared`**, so a request validated by the
  API and a form validated in the browser cannot drift apart.
- **Design values come from the handoff.** `apps/web/src/styles/tokens.css` is a
  verbatim copy; never edit token values there.
- **`/api/mobile/*` is a frozen contract** for the existing mobile client.
- **Never edit `apps/api/generated/`** — it is regenerated by
  `npm run db:generate`.

Before opening a pull request, run `make verify`. CI runs the same checks plus a
production build of both Docker images.
